# wechatbot-new 开源问题检查与整改方案

> 检查时间：2026-09-18  
> 当前仓库版本：`v2.2.5`（`5b85e3e`）  
> 检查方式：对照 GitHub/PyPI 公开仓库、本地源码、`.gitignore`、以及本次本地试用产生的未提交改动  
> 本文只出方案，**不改代码**

---

## 1. 结论

本地试用已经能走通「WebUI 启动 → 配置监听对象 → 私聊/群聊收发 → 核心记忆写入」主路径，说明兼容层（`wxbot.py` + `wechatauto-replica`）在你这台机器上是可用的。

但当前工作区还**不能直接提交/发布**。主要卡点不是功能缺失，而是：

1. **本地试用数据已经污染了开源该提交的文件**（真实 API Key、微信昵称、聊天记忆、自用 Prompt）。
2. 仓库里仍有一批 **开源工程问题**：密钥管理、忽略规则、文档过时、启动入口不一致。
3. 兼容层仍有若干 **功能宣称与实现不符**（语音转文字、合并转发、自动更新、定时重启）。
4. 本地试用还暴露了一个真实启动缺陷：`config_editor.py` 用 `'python'` 拉起 bot，在 venv / Windows Store Python 环境下会失败。你本地已经改成 `sys.executable`，这条应保留。

**发布前最低要求：** 先把密钥作废并还原 `config.py`，再把试用产物移出版本库，然后按下面 P0 → P1 顺序改。

## 3. 问题清单

优先级说明：

- **P0**：不处理就不能公开提交 / 不能再发版
- **P1**：会影响真实用户使用，或文档会误导用户
- **P2**：工程卫生、合规、可维护性
- **P3**：体验优化，可排期

### P0 开源发布阻断项

#### P0-1 真实密钥与会话数据还在工作区

`config.py` 当前不是仓库默认值，而是本地试用值：

- `DEEPSEEK_API_KEY` 已变成真实 Key（`sk-` 开头）
- `LISTEN_LIST` 变成 `[['ceshi', 'AI'], ['哈', 'AI']]`
- `DEEPSEEK_BASE_URL` / `MODEL` 被改成官方 DeepSeek
- `GROUP_CHAT_RESPONSE_PROBABILITY` 从默认 `0` 改成 `100`

`CoreMemory/` 里还有真实对话摘要。`.gitignore` **挡不住** `config.py`（它本来就被跟踪），也挡不住 `CoreMemory/`（忽略规则写的是小写 `core_memory/`，Windows 下 Git 默认大小写敏感配置时仍可能漏）。

**风险：** 一旦 `git add -A` / `git commit`，密钥和聊天记忆会进 Git 历史；若再 push / 打 PyPI 包，等于公开泄露。

**整改：**

1. 立刻在 DeepSeek 控制台作废并轮换该 Key（即使还没 push，也已经出现在本地文件和本次检查记录中）。
2. 把 `config.py` 恢复成仓库默认占位值，或改成 `config.example.py` + 本地 `config.py` 被忽略。
3. 确认 `CoreMemory/`、`Memory_Temp/`、`chat_contexts.json`、`recurring_reminders.json`、试用 Prompt **永远不进版本库**。

#### P0-2 `.gitignore` 与真实运行目录对不上

当前忽略规则：

```
chat_contexts.json
user_timers.json
core_memory/
memory_temp/
forum_data/npc_config.json
```

代码里实际目录/文件是：

- `CORE_MEMORY_DIR = 'CoreMemory'`
- `MEMORY_TEMP_DIR = 'Memory_Temp'`
- `recurring_reminders.json`（未忽略）
- `forum_data/` 下还有角色论坛 JSON、头像，不只 `npc_config.json`

结果：本地试用产生的核心记忆已经变成未跟踪文件，一不小心就会被加进去。

**整改：** 按真实大小写补齐忽略规则，并加一层「运行时数据目录」约定。

#### P0-3 `config.py` 同时充当「示例配置」和「运行配置」

这是本次试用把仓库弄脏的根因。开源项目里，被 Git 跟踪的 `config.py` 只要用户改过，就永远处于 dirty 状态。

**建议目标结构：**

```
config.example.py     # 入库，只有占位符
config.py             # 本地生成，gitignore
config.py             # 若暂时不拆文件，至少提交前必须还原占位符
```

配套改 WebUI：首次启动若没有 `config.py`，从 example 复制一份。

#### P0-4 二进制启动器与帮助页来源不明

仓库跟踪了 `Run.exe`，README 还把它写成主启动方式。开源仓库放未提供源码的 exe，会带来：

- 供应链信任问题（用户无法审计）
- Windows Defender / 浏览器下载拦截
- 与 PyPI 入口 `wechatbot-webui` 双轨，文档更混乱

另外 `templates/bzwd.html` 是从外部站点另存的 VitePress 页面，引用了：

- `mitay.net` 的 CSS/字体（和本项目无关）
- `51.la` 统计脚本
- `templates/files/js-sdk-pro(1).min.下载` 这种浏览器下载残留文件名

帮助页在本地基本是残页，还夹带第三方追踪。

**整改：** 明确 `Run.exe` 是否继续提供；帮助页改成项目内 Markdown/静态页；删除 `.下载` 残留。

### P1 功能与启动缺陷（本地试用已碰到或文档会骗人）

#### P1-1 Start Bot 在 venv 下可能启动失败

仓库原逻辑：

```python
cmd = ['python', bot_py]
```

你本地已改为：

```python
cmd = [sys.executable, bot_py]
```

这是有效修复。Windows 上经常没有全局 `python`，只有当前解释器或 `py`。

同文件还有两处同类问题，仓库里还没改：

- `bot.py` 定时重启 / 指令重启：`os.execv(sys.executable, ['python'] + sys.argv)`
  第一个参数用了当前解释器，argv[0] 却写死 `'python'`，部分环境下重启会错进程。

**整改：** 统一用 `sys.executable`，argv 也用它；提交时只带这一处修复，不要夹带 `config.py`。

#### P1-2 `bot.py` 在 import 时就初始化微信，失败直接 `exit(1)`

`WeChat()` 写在模块顶层，不在 `main()` 里。后果：

- `python -c "import bot"`、PyPI 入口 `wechatbot = bot:main` 都会先连微信
- 微信没登录时，进程在进入 `main()` 之前就退出
- 错误文案仍写「要求版本: 微信4.1.2」，和 README 的 4.1.12.26 不一致
- 仍引导用户「重启 Run.bat」，但仓库主路径已经是 `Run.exe` / `python config_editor.py`

**整改：** 把微信初始化移进 `main()`；错误信息改成当前兼容版本和当前启动方式。

#### P1-3 语音 / 合并转发 / 自动更新 / 定时重启名存实亡

| 文档宣称 | 实际代码 |
|---|---|
| 接收语音消息（依赖微信「语音转文字」） | `WxMessage.to_text()` 对 voice 直接返回空字符串 |
| 合并转发识别 | `get_messages()` 返回的 `_merge` 从未赋值，恒为 `None` |
| 自动更新程序 | 仓库无 updater，只有 CHANGELOG 旧记录 |
| 定时重启 | 配置默认 `ENABLE_SCHEDULED_RESTART = True`，但启动处写死 `if False and ENABLE_SCHEDULED_RESTART` |
| 一键检测 | UI 按钮已注释，代码仍找 `一键检测.bat`，仓库里没有这个文件 |

**整改：** 要么补实现，要么 README/CHANGELOG/WebUI 明确标成「未接入 / 已禁用」。开源项目里，文档夸大比缺功能更伤信任。

#### P1-4 图片和表情在空 content 时会被静默丢弃

`message_listener()` 在分发到 `handle_wxauto_message()` 之前：

```python
if not original_content:
    logger.info("消息内容为空，已忽略。")
    return
```

微信 4.x 数据库里，图片/表情的 `content` 经常为空。这会让识别逻辑根本走不到 `msg.download()` / `msg.capture()`。  
本地群聊试用里的「空白消息」，很大概率就是这条路径。

即便 content 非空、进入识别：

- 识图走 `MOONSHOT_API_KEY`，默认仍是 `YOUR_API_KEY`
- `ENABLE_IMAGE_RECOGNITION` / `ENABLE_EMOJI_RECOGNITION` 默认 True

用户会看到「收到了但没识别 / 机器人说这是空白」。

**整改：**

1. `image` / `emotion` 即使 content 为空也要进入下载/截图流程。
2. 对应 Key 未配置时，启动时告警并自动关闭识图，而不是运行中 401。
3. 默认关闭未配置好的可选能力：联网、辅助模型、识图。

#### P1-5 默认配置对新人太「全开」

仓库默认（未试用前）已经是：

- `ENABLE_ONLINE_API = True`，Key = `YOUR_API_KEY`
- `ENABLE_ASSISTANT_MODEL = True`，Key = `YOUR_API_KEY`
- `ENABLE_IMAGE_RECOGNITION = True`
- `GROUP_KEYWORD_LIST = ['樊伊航', '机器人', '人机']`（原作者昵称进了默认配置）
- `ENABLE_LOGIN_PASSWORD = False`，但 `LOGIN_PASSWORD = 'YOUR_PASSWORD'` 仍写在会被提交的文件里

**整改：** 可选功能默认关闭；关键词改成中性示例；密码字段不要出现在示例配置的有效值里。

#### P1-6 GitHub Issue #1 已修但未关闭

[Issue #1](https://github.com/fanyuantaier/wechatbot-new/issues/1)（首条消息判断聊天类型约 40 秒）已在 `v2.2.4` 用 `GetListenChatType()` 修掉，Issue 仍 Open。

代码主路径已优先读监听缓存；只有未监听对象才会回退 `GetAllSubWindow()`（最多 50 个会话）。

**整改：** 在 Issue 里回一句「已于 2.2.4 修复」并关闭，避免后来者以为线上还没修。

#### P1-7 版本号三处不一致

- `pyproject.toml` / `CHANGELOG.md`：`2.2.5`
- `config_editor.py` 启动横幅：`version：2.2.4`
- README 功能列表仍写自动更新、语音等旧能力

**整改：** 单一版本源，WebUI 从 `pyproject.toml` 或常量读取。

### P2 工程、安全、合规

#### P2-1 PyPI 包装进了不该发布的模块

`pyproject.toml`：

```toml
py-modules = ["bot", "config", "config_editor", "run", "test_bot", "wxbot"]
```

问题：

- `test_bot.py` 是本地联调脚本：硬编码 `D:\WeChatBot-main`，会真实 `SendMsg` 到「文件传输助手」
- `__init__.py` 只有 `os.system('Run.exe')`。若将来改成包导入，`import wechatbot` 会直接跑 exe
- `run.py` 只是 `WeChat().KeepRunning()`，没有配置、没有 bot 逻辑，却容易被当成正式入口
- `include-package-data` 几乎全量打包；一旦 `CoreMemory/` 没忽略干净，记忆文件会进 wheel

**整改：** 测试脚本移出包装清单；`__init__.py` 改成包说明或删掉；运行时数据目录永不进 `package-data`。

#### P2-2 依赖与许可证文档过时

| 文件 | 问题 |
|---|---|
| `requirements.txt` | `wechatauto-replica[guia]>=1.0.4` |
| `pyproject.toml` | `>=1.2.0`（2.2.5 的 WAL 修复需要这个） |
| `LICENSE_COMPLIANCE.md` | 仍写 wxautox / wxauto 智能导入、`Run.bat` |
| `DEPENDENCIES.txt` | 项目名还是 `WeChatBot_WXAUTO_SE`，日期 2025-09 |
| `LICENSE` | 主页仍指向 `iwyxdxl/WeChatBot_WXAUTO_SE` |
| `bot.py` | `PROJECT_NAME = 'iwyxdxl/WeChatBot_WXAUTO_SE'` |

用户按 `requirements.txt` 安装，可能装到没有 2.2.5 修复的旧库，重新遇到 WAL 死循环。

**整改：** 三份依赖声明对齐到 `>=1.2.0`；合规文档改成只描述 `wechatauto-replica`。

#### P2-3 WebUI 安全基线偏弱

当前可接受的前提是「本机 127.0.0.1 自用」。作为开源项目仍建议补：

- `/start_bot`、`/stop_bot`、`/bot_status`、`/bot_heartbeat` **没有** `@login_required`。一旦有人打开登录密码，这些接口仍能未授权调用。
- `app.secret_key = os.urandom(24)`，每次启动会话失效；密码开启时用户会反复登录。
- `kill_process_using_port(PORT)` 会杀掉占用该端口的任意进程，可能误杀别的本地服务。
- 核心记忆 API 只检查文件名后缀 `_core_memory.json`，未规范化路径，理论上可 `../` 穿越。
- 网页抓取会请求用户消息里的任意 URL（SSRF 到内网）。对微信机器人是特性，但应对 `localhost` / 私网地址做拒绝。
- `get_dynamic_config()` 使用 `eval()` 读 `config.py`。`config.py` 本身就是代码，风险主要是「WebUI 写配置 + 动态 eval」这条链，应改成 `ast.literal_eval`。

**整改：** 先修鉴权和路径规范化；SSRF 黑名单作为第二批。

#### P2-4 帮助文档、卸载脚本、测试脚本不适合直接开源展示

- `uninstall_all_packages.bat`：`pip freeze` 后卸载**当前环境全部包**，文案还叫用户去跑已经不存在的 `Run.bat`
- `test_bot.py`：会向真实微信发消息
- 仓库没有单元测试、没有 CI、没有 `CONTRIBUTING`

**整改：** 卸载脚本改成只卸本项目依赖，或直接删除；测试改成 mock；至少加一个 GitHub Issue 模板。

#### P2-5 默认 Prompt 被本地删掉，仓库示例会断

Git 里默认 `LISTEN_LIST = [['你的微信昵称', '角色1']]`，对应 `prompts/角色1.md`。  
本地已删除 `角色1.md` / `角色2.md` / `大哥.md` / `抽象的女的.md`，另存了自用 `AI.md`、`企业_1.md`。

若误把删除提交上去，新用户按 README 选「角色1」会直接启动失败（`main()` 会因 prompt 文件不存在 `FileNotFoundError`）。

**整改：** 保留 1～2 个中性示例 Prompt；自用角色只放本地，不入库。

### P3 体验与代码质量（可排期）

1. **`bot.py` 过大（约 4300 行）**，配置、消息、记忆、提醒、心跳全在一个文件，后续 PR 很难审。
2. **群聊类型缓存**只在 `IGNORE_GROUP_CHAT_FOR_AUTO_MESSAGE` 时预热；普通群聊仍可能在首条消息走一次判断。
3. **`GetAllSubWindow()` 只取 50 个会话**，回退路径在会话很多时仍可能找不到。
4. **表情归档写死** `~/Documents/wechatauto_media/emoji`，用户无配置入口。
5. **启动横幅**仍有「买来你就被骗了，倒卖死全家喔」这类语句，开源项目不合适。
6. **无 `CONTRIBUTING` / 安全披露说明 / 微信 ToS 风险提示**（自动化控制微信客户端本身就有封号风险，README 只在启动横幅提了一句小号）。
7. **无自动化测试**。至少应对 `wxbot.WxMessage` 的类型映射、空 content、群聊 @ 解析做纯函数测试。

## 4. 建议整改路线（仍先不改代码）

### 阶段 0：当天，发布前消毒（必须先做）

1. 作废并轮换 DeepSeek API Key。
2. `config.py` 恢复为仓库占位值，或确认后续改为 example + 本地文件。
3. 把 `CoreMemory/`、试用 Prompt、聊天上下文移出仓库目录（或确保 ignore 生效）。
4. **不要** `git add -A`。若要提交，只挑 `config_editor.py` 的 `sys.executable` 修复。
5. 自用 Prompt / 记忆留在本机，不要当默认角色提交。

### 阶段 1：开源可发布基线（建议下一轮改代码时做）

1. 拆分 `config.example.py` / 忽略 `config.py`。
2. 修正 `.gitignore`：`CoreMemory/`、`Memory_Temp/`、`forum_data/`、`recurring_reminders.json`、`*.tmp`、`config.py`。
3. README 按真实能力重写启动步骤：`python config_editor.py` 或 `pip install` 后的 `wechatbot-webui`；`Run.exe` 单独说明来源。
4. 依赖三处对齐到 `wechatauto-replica[guia]>=1.2.0`。
5. 关闭或标明：语音转文字、合并转发、自动更新、定时重启、一键检测。
6. 更新 `LICENSE_COMPLIANCE.md` / `DEPENDENCIES.txt` / LICENSE 项目地址。
7. 关闭 GitHub Issue #1。
8. WebUI 版本号改为 2.2.5。
9. 删除或替换 `bzwd.html` 与 `templates/files/*.下载`。
10. `test_bot.py` 移出包装清单，去掉硬编码路径。

### 阶段 2：本地试用暴露的功能修复

1. 空 content 的图片/表情不再丢弃。
2. 未配置的可选 API 启动时自动降级并打明确日志。
3. 微信初始化移入 `main()`。
4. 重启逻辑统一 `sys.executable`。
5. 默认关闭联网 / 辅助模型 / 识图；关键词改中性示例。

### 阶段 3：安全与工程化

1. 给 start/stop/status 补上与登录开关一致的鉴权。
2. 核心记忆/Prompt 路径做 `realpath` 约束。
3. 网页抓取拒绝回环和私网地址。
4. `eval` 改为 `ast.literal_eval`。
5. 端口占用改为提示，而不是直接 kill。
6. 增加最少的单元测试和 Issue 模板。

## 5. 发布前检查清单

提交或打 tag 前，人工过一遍：

- [ ] `git diff` 里没有 API Key、微信昵称、聊天记录、用药/私人对话
- [ ] `git status` 没有 `CoreMemory/`、`Memory_Temp/`、`chat_contexts.json`
- [ ] `config.py`（或 example）全是占位符
- [ ] 默认 Prompt 还在，且 `LISTEN_LIST` 能对上文件名
